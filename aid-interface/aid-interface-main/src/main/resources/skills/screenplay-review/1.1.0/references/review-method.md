# 证据化审核方法

## 一、冻结范围

先确认当前审核的是哪份正文、项目类型、当前集和用户点名范围。只把用户明确要求、已接受上下文和待审正文当作事实。缺少某项输入时，只把依赖该输入的结论标为待确认，其他维度继续审核。

## 二、规则性质

- `STRUCTURAL`：可直接证明的结构与格式完整性，例如首行、场标题、说话人、明确前后冲突。
- `OBJECTIVE`：需要引用正文判断但有可复核结果，例如因果断裂、知识越界、关键物件无来源、明确时限不可能。
- `CRAFT`：通常有效但可被创作者有理由覆盖的写作方法。
- `AESTHETIC`：节奏、留白、旁白、类型惯例、人物讨喜程度等创作者选择，不能单独触发自动修复。

## 三、先机械，后语义

先检查：AID 第一行、场标题、说话人、缺失正文、明确重复或断号、当前集范围、显式连续性冲突。

再检查：观看承诺是否兑现、人物行动是否导致下一状态、场景是否有必要变化、核心阻力是否有因果地失效、心理是否可表演、对白策略是否变化、结尾是否保留结果和代价。

不要因为安静场没有对手、开放结局没有新事件、单一场景没有换地、类型作品使用惯例就判错；先看它是否完成必要功能。

## 四、问题格式

第一行输出：

`审核结论：APPROVE|APPROVE_WITH_NOTES|REVISE|PROVISIONAL`

每个问题按以下字段输出：

`[F-001] MAJOR | OBJECTIVE | 因果`

- `位置：场次 N / 人物名或动作锚点`
- `证据：仅引用证明问题所需的短句或前后冲突事实`
- `影响：说明观众理解、人物行动、连续性或下游制作会损失什么`
- `修订目标：说明修复后必须恢复的结果和必须保留项，不代写整场`

严重程度为 `BLOCKER`、`MAJOR`、`MINOR`、`NOTE`。重复问题合并，不为同一根因拆出多条。

## 五、结论与机器标记

- `APPROVE`：没有问题。
- `APPROVE_WITH_NOTES`：只有不阻断的 `MINOR/NOTE` 或审美建议。
- `REVISE`：存在可定位的结构或客观重大问题。
- `PROVISIONAL`：关键输入缺失，无法完成依赖它的主要判断。

`REPAIR_REQUIRED: YES` 只用于存在 `STRUCTURAL/OBJECTIVE` 的 `BLOCKER` 或 `MAJOR`，且修订目标唯一、无需用户选择；小问题和审美偏好不能触发自动修复。

`AESTHETIC_CHOICE_REQUIRED: YES` 只用于确有两个以上都成立但会改变作者意图的方向，需要用户决定。报告最后严格各占一行：

`REPAIR_REQUIRED: YES|NO`

`AESTHETIC_CHOICE_REQUIRED: YES|NO`

# AID 剧本运行契约

## 权威顺序

发生冲突时按以下顺序处理：

1. 用户本轮明确写出的事实、必须项、禁止项和修订范围；
2. 项目中已接受的当前剧本及当前集上下文；
3. 用户显式附加的参考材料；
4. Skill 的创作方法和默认建议。

创作方法不能反过来补造输入没有建立的关系、能力、证据、权限、精确时间、资源或机关。

## 编排模式

- `NORMAL`：写作子 Skill 生成或修订，交稿前只做静默自检。
- `HIGH`：写作完成后由只读审核子 Skill 独立检查；仅当报告给出客观、可定位且阻断交付的硬伤时，最多执行一次 `REPAIR`。
- `REVIEW_ONLY`：审核现有正文并给出问题报告，绝不生成替代稿。

每次实际模型调用都是独立 AID 媒体任务。根 Run 只记录编排步骤与任务关联，不创建平行的排队、计费或退款状态机。

## 版本和权限

- 根版本固定绑定子 Skill 的不可变版本；进行中的 Run 不跟随 current pointer 漂移。
- INTERNAL 子 Skill 不能被用户、Web 或 CLI 绕过根入口直接调用。
- 子调用只能继承或收窄项目、剧集、资源和模型权限，禁止扩大范围或递归调用根 Skill。
- 审核与修复不输出模型私有思维链，只保留结论、证据和可执行修改目标。

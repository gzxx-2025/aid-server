# 动态询问策略

询问的目标是取得会改变执行结果的决定，不是把表单字段逐个念给用户。

## 先判断，再询问

将当前信息分为三类：

- 已知事实：项目类型、项目名、当前集、已接受剧本、用户已经给出的类型和风格。直接复用，不再问。
- 可安全默认：措辞强弱、非关键环境细节、未指定但可在后续局部调整的表现选择。由模型决定，并保持可回退。
- 必须由用户决定：目标集不明确、两个故事方向会产生不同事实、审核对象缺失、修改范围互斥或审美选择会重写作者意图。只询问这些项。

## 问题包

- 一轮最多 4 个问题，最多两轮；能执行时直接执行，不为凑满轮次而提问。
- 每个问题包含稳定字段、问题、为什么需要、输入类型、候选项、推荐值和是否允许自定义。
- 选项必须互斥且使用用户能理解的剧情语言，不暴露数据库 ID、内部路由或模型推理。
- 推荐项说明影响，但不替用户决定不可逆的剧情分叉。
- 时长只在用户主动指定或当前创作必须受时长约束时使用；不能把“多少秒”设成每次必答题。

## 对话体验

- 同一答案不重复询问；上下文修订后只重问受影响字段。
- 用户说“你决定”时，只对允许 AI 决定的可回退项采用推荐值。
- 用户提供了足够的故事意图时，模型应直接写，不要求先补齐完整人物小传、节拍表或生产参数。
- 前端按结构化问题渲染选择、文本或数字控件；API 与 CLI 使用同一字段与恢复语义。

# 修订、规范化与客观修复

## 共同原则

先列出本轮允许变化的目标与必须保留的事实，只在内部使用，不输出修订日志。修订后的每个变化都应能追溯到用户要求或独立审核中的明确证据。最终交付完整的修订目标正文，不输出差异补丁、修改清单或只含被改场次的残片。

### `REWRITE`

- 定位用户点名的场、人物、对白、节奏或问题类型。
- 先修根因，再处理必要的前后衔接；不以“整体更好”为由重写无关内容。
- 保留作者语言习惯、人物声音、既有事实、场景功能和未点名的开放空间。
- “去 AI 味”不是换同义词或删除所有类型惯例，而是修复可定位的重复因果、同构策略、过度解释、过度工整和代价即时结清。

### `NORMALIZE`

- 只识别原文中的场景、动作、说话人、对白、画面文字和必要转场，再映射到 AID 规范格式。
- 保留原句、顺序和段落功能；不补剧情、不改说话人、不新增关系或动机。
- 原文含混到无法可靠判断说话人或场景边界时，不凭空决定语义。当前调用若已越过询问阶段，只保留含混内容为普通叙事，避免制造错误事实。

### `REPAIR`

- 只处理审核报告中有正文位置、冲突证据、影响和明确修订目标的客观硬伤。
- 可修复项包括：AID 格式不可解析、前后事实冲突、人物知识越界、时空因果断裂、关键物件无来源、明确时限与动作容量矛盾。
- 不自动处理魅力、气质、节奏偏好、开放程度、人物是否讨喜等审美分叉。
- 如果报告同时含客观问题和审美建议，只改客观问题；最多本轮一次，并保留未命中部分。

## 回归检查

修订后核对用户要求、原有场景职责、人物知识、关键物件、进入/退出状态和 AID 格式是否仍在。修短不等于准确，增加细节也不等于更可拍；以是否保留故事义务和消除根因为准。

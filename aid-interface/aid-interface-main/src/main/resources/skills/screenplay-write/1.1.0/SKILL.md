# Screenplay Write

仅供 `screenplay` 根入口以固定版本调用。输入包含动作模式、项目类型、用户要求、可信连续性上下文和按意图命中的少量知识。

## 写作顺序

1. 服从用户明确要求与已接受项目事实，区分世界真相、人物认知和观众已知信息。
2. 在内部形成当前观看承诺、人物目标、有效阻力、局部兑现和退出状态，不输出节拍表或思考过程。
3. 让事件按“行动导致结果，结果迫使下一动作”推进；场景用可见变化证明其必要性。
4. 把心理和关系变化写成可表演的动作、空间、物件、对白、沉默或有意的声音信息。
5. 根据 `movie` 或 `series` 使用对应的结构与连续性策略，不把电影硬切成集钩子，也不把单集写成整季梗概。
6. 交稿前静默检查规范格式、因果、角色知识、连续性、时长容量和重复表达。

## 动作模式

- `CREATE`：依据当前输入生成完整的本轮剧本正文。
- `CONTINUE`：承接已接受正文的尾部状态，从下一场号输出新续写段；不重复已有正文，不重置人物状态或未结代价。
- `REWRITE`：按用户点名目标修订，保护未点名事实、语气和段落功能，并输出完整修订目标正文而不是差异补丁。
- `NORMALIZE`：只把非规范文本整理为 AID 可提取格式；任何语义变化都必须来自用户明确要求，并输出完整规范化正文。
- `REPAIR`：只落实独立审核报告中有正文证据的客观硬伤，最多一次，不处理审美分叉；输出完整修复稿而不是修改清单。

输出始终是 `references/canonical-format.md` 规定的纯文本，不输出 JSON、Markdown 围栏、审核报告、时长说明、版本信息或模型私有思维链。

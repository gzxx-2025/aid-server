# 公开模型官方能力核验台账

核验日期：2026-09-08

## 1. 范围与使用规则

本台账只记录系统公开供应商目录中已经存在的模型，依据供应商官方模型页、API 文档和随项目留存的官方文档快照核验。它不包含密钥、网关覆盖值、价格、倍率、模型池或部署信息，也不把“目录中存在”解释为“协议已经接通”。

状态定义：

- **已表达**：现有结构化能力字段能够完整表达，或 `050-verified-model-capabilities.sql` 会在字段缺失时补齐。
- **部分表达**：官方约束已核验，但当前公共能力契约不能无损表达，或者 Provider 请求链尚未实现；模型不得据此自动启用。
- **待核验**：现有官方资料不足以确认精确边界，保持原配置，不猜测上限。

执行规则：所有已知数量、单项时长、总时长、尺寸、格式、大小和组合上限都应在报价、提交和重试恢复共用的校验链中拒绝超限输入；不得截断、忽略或缩短后调用上游。SQL 只补缺失字段，不覆盖站长已有值。

## 4. 已确认的契约缺口与迁移事项

以下内容有官方依据，但不能由当前 `CapabilityVO` 无损表达，不能用近似值写入配置：

1. 文件大小虽已支持小数 MB，但仍需区分 URL 文件、Base64 解码数据和整个 HTTP 请求体；因此即梦的 4.7MB 与 Vidu 的传输方式上限不能无差别写入同一字段。
2. 时长已经支持小数秒；仍需要开区间能力，以表达“大于 1 且小于 600 秒”。
3. 需要总请求大小、图片总像素、视频总像素、页数、跨素材尺寸比、输入与输出合计数量等字段。
4. 需要分组计数和条件规则，例如 Gemini 高保真子集、Vidu 主体及每主体图片、语言对应提示词上限、关键帧分段时长。
5. 需要结构化依赖/互斥规则，例如万相顺序输出与思考/调色板互斥、4K 仅纯文生图、Agnes 场景互斥。
6. 输出尺寸档位和固定像素约束必须分开；`2K`、`1440P` 和具体宽高不能全局互换。
7. Gemini/OpenAI 文本多模态、Vidu 口型、Agnes 场景、万相视频编辑音频策略等必须在 Provider 请求协议接通并通过真实 payload 单元测试后，才可把相应能力标为可用。

## 5. SQL 变更语义

`sql/v2.1.0.sql` 中的官方能力迁移仅对精确供应商代码和模型代码命中的合法 JSON 对象执行更新。每个字段使用 MySQL 5.7 的 `JSON_INSERT`，只插入不存在的路径；并且只在至少一个目标字段缺失时更新、递增配置版本。非法 JSON 不会被自动替换为空对象，其他能力扩展字段不会丢失，状态、倍率、计费、SKU、模型池、网关和凭证均不修改。

SQL 没有写入的已核验约束，必须先完成上节公共契约或 Provider 请求迁移；在此之前保留原配置，并在启用检查中标记为未完整核验。

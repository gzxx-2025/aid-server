# TokenDance 模型能力与成本 SKU 核验台账

核验日期：2026-09-09

## 1. 资料优先级

模型能力严格按以下顺序核验：

1. 项目留存的对应原厂官方文档快照，与 TokenDance AI 接入索引交叉核对；
2. TokenDance AI 接入索引所链接的具体协议和模型资料；
3. 索引追溯到的模型原厂官网或原厂公开代码仓；
4. 仅针对原厂域名和原厂模型名称进行互联网检索；
5. 原厂没有公开资料时，以 TokenDance 模型页和渠道协议资料兜底。

第三方聚合商、非原厂代理和站点专用供应商资料不作为能力依据。能力资料中没有公开数量、时长、大小、格式或组合上限时保持字段为空，不把示例值推断成官方最大值。

运行时来源清单位于 `aid-interface/aid-interface-main/src/main/resources/tokendance/catalog/official-source-index.json`；每个模型的成本和来源时间位于 `cost-snapshot.json`；显式媒体能力和组合规则位于 `verified-capabilities.json`。

## 2. 当前覆盖结论

| 项目 | 数量 | 结论 |
|---|---:|---|
| 本地目录模型 | 82 | 已排除 Embedding、搜索/网页读取和文档解析用途 |
| 模型－协议组合 | 141 | 每个组合都可独立预览和导入 |
| 成本 SKU 完整组合 | 141 | 全部通过成本编译审计，没有“SKU 不完整将停用”的组合 |
| 能力状态为 `VERIFIED` 的模型 | 50 | 当前写入字段有原厂或 TokenDance 渠道依据 |
| 能力状态为 `PARTIAL` 的模型 | 32 | 未公开的精确边界保持为空，不影响已完整成本 SKU 的判定 |
| 能力状态为 `UNVERIFIED` 的模型 | 0 | 每个目录模型至少有原厂或 TokenDance 渠道证据入口 |
| 静态协议路由 | 17 | 文本、图片、视频、配音及音色协议均在 TokenDance 独立命名空间内实现 |
| 真实收费联调 | 0 | 本轮未使用真实 Key 发起收费调用，不把静态接通标记为实测成功 |

能力状态、成本 SKU 状态、模型启用状态和真实联调状态是四个独立维度：

- `PARTIAL` 通常表示原厂没有公开某个精确限制，不等于缺价；
- `pricingComplete=true` 表示该模型－协议的本地成本能安全转换为现有计费规则；
- 目录导入仍按产品约定创建为停用模型，由站长核对后显式启用；
- 既有模型不会因再次导入而覆盖能力、SKU、倍率、状态、模型池或自定义网关。

## 3. 协议覆盖

| 类型 | TokenDance 协议 |
|---|---|
| 文本与多模态理解 | `openai:chat-completions`、`openai:responses`、`anthropic:messages` |
| 图片生成 | `ark:image-generations`、`openai:image-generations` |
| 视频生成 | `seedance:generations`、`kling:text2video`、`kling:image2video`、`kling:omni-video`、`wan3:video-synthesis`、`happyhorse:video-synthesis`、`minimax:video_generation_v2` |
| 配音与音色 | `minimax:t2a_v2`、`minimax:t2a_v2_ws`、`minimax:voice_clone`、`ark:tts`、`ark:tts_ws`；MiMo 三种音频语义通过专用音频门面复用 Chat 路径 |

协议实现包含请求字段白名单、响应与用量解析、同步/异步终态、错误恢复动作和固定 `X-App-URL` 归因。协议差异只在 TokenDance 供应商命名空间内生效，不改变其他供应商请求。

## 4. 重点模型能力

### Seedance

- Seedance 2.0、2.0 Fast、2.0 Mini 和 2.5 分别维护清晰度、比例、输出时长、图片/视频/音频数量、单段和总时长、文件大小、画面尺寸、帧率及混合素材规则。
- 已知超限在报价、提交和恢复前统一拒绝，不裁剪图片、视频或音频继续调用。
- Seedance 2.5 当前渠道公开 480P、720P、1080P，三档均进入像素与帧率 Token 估算，并分别覆盖含输入视频和不含输入视频的成本 SKU。
- 视频 Token 预冻结使用已核验像素、帧率、输出秒数和输入视频最低计费秒数；完成后以供应商 `completion_tokens` 结算并退回多冻结部分。

### Seedream 5.0

- Pro：Ark 协议支持文本、最多 10 张参考图、1K/2K、自定义宽高、PNG/JPEG；不支持组图、流式或联网搜索。
- Lite：Ark 协议支持文本、最多 14 张参考图、2K/3K/4K、自定义宽高、组图和流式输出。
- 本轮排除搜索/网页读取能力，因此 Lite 的 `web_search` 参数不会进入模型能力或价格规则，传入时在协议白名单阶段拒绝。
- TokenDance 文档没有声明 Lite 组图绝对最大张数，模板不把示例中的 3 或 4 张写成官方上限；系统仅保留通用安全上限。
- OpenAI Images 兼容协议按实际适配声明为文生图，不错误暴露 Ark 多参考图、组图和流式字段；成本按同模型 Ark 每张成本转换并写明来源说明。

### Kling 3.0

- 文生和图生协议分别校验提示词、720P/1080P/4K 支持差异、3–15 秒、16:9/9:16/1:1，以及图片输入与首尾帧边界。
- Omni 区分文生、图生、首尾帧、主体参考、特效视频和视频编辑场景；校验 `elements` 类型、素材引用、最多一个视频、图片/视频组合及音频模式。
- 特效视频要求关闭音频并开启多镜头；视频编辑固定关闭多镜头并只接受关闭或保留原音的音频模式。
- TokenDance 当前文生/图生渠道没有声明音画同出时，能力不会沿用其他渠道的 `supportsAudio=true`。

### Wan3、HappyHorse 与 MiniMax 视频

- Wan3 和 HappyHorse 按实际任务协议保留场景、图片/视频数量、时长、清晰度、输出格式和音频开关。
- MiniMax H3 渠道型号按 TokenDance V2 协议校验提示词、480P/768P、时长、比例及首尾帧；原厂没有对应渠道型号页或文件边界时保持为空，不套用另一个型号的限制。

### 文本与多模态理解模型

- Qwen、DeepSeek、GLM、Kimi、MiniMax、Step、Seed、MiMo、混元、LongCat、Ling、Spark 和 Dots 按原厂资料记录文本/图片/视频/音频输入、上下文、最大输出、流式、工具、结构化输出、缓存和思考控制。
- Chat Completions、Responses、Anthropic Messages 各自过滤协议不支持的字段；媒体消息仅在模型能力与协议同时允许时发送。
- 原厂没有公开逐模型媒体数量或文件上限时不写 `-1` 或虚构数值；已公开的限制仍由公共能力校验层执行。

### 配音、音色设计与克隆

- 配音、注册式复刻、参考样本克隆和声音设计是独立操作，不能用一个“参考音频”开关代替。
- 能力模板结构化记录文本/音色是否必填、内置音色、音频格式、采样率、流式、时间戳、语速、音量、音调、情绪、参考样本格式与大小。
- MiniMax Speech 2.8 HTTP/WebSocket、MiniMax Voice Clone、Seed TTS 单向/双向，以及 MiMo TTS/声音设计/参考克隆均进入统一音频能力校验。
- 后台音色任务由站长承担供应商成本，不扣 C 端积分；注册结果不确定时不重复提交，音频转存失败时不重新生成。

## 5. 成本 SKU 规则

成本快照类型固定为 `model_call_cost`，不是分润价。编译器覆盖：

- 输入、输出、缓存读取、缓存写入、推理 Token；
- Token 上下文阶梯，并把同一区间的输入/输出/缓存价格合并成互不重叠的 SKU；
- 每张、每秒、每千字、按次、输出像素阶梯、输入图片附加费；
- 声音复刻的固定注册费与试听字符费；
- Seedance 的视频 Token 估算与供应商用量结算。

Responses、Anthropic Messages 或 OpenAI Images 没有重复列出同模型价格时，只在同一 TokenDance 模型内复用已经公开的兼容协议成本，并在 SKU 备注中说明；不会跨模型、跨供应商猜价。

已导入且 SKU 为空或全部停用的目录模型，可以在预览中执行“修复目录 SKU”。更新使用 `configVersion`，只提交计费字段；能力、倍率、状态和管理员扩展字段保持不变。

## 6. 启用与验收边界

目录不会自动启用模型。站长启用前仍应完成：

1. 已绑定当前 TokenDance 凭证，所选模型－协议的 `pricingComplete` 为真；
2. 核对 `PARTIAL` 中与自身业务输入有关的未公开边界，必要时在后台补充保守限制；
3. 使用有效账号对协议提交、查询、结果、错误、用量和恢复响应头做一次真实联调；
4. 确认站点倍率、模型池和功能池配置；
5. 用上限和上限加一验证所有已知图片、视频、音频、时长、大小与组合规则。

本轮没有执行收费调用、充值付款、生产数据库更新或正式发布。
